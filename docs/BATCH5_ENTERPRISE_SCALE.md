# 第 5 批：规模化与企业运维

> 承接审计报告第 4 批末尾列出的剩余项（自定义字段 / 项目集 / 备份恢复）。
> 这三项都属于"客户规模上来之后才痛、但回头补成本很高"的能力。

## 一、自定义字段

### 为什么现在做

字段写死在实体与前端表单里，客户加一个「影响模块 / 客户名称 / 复现环境」就要改表、改接口、改前端发版。
这是**平台化与做项目的分水岭**，也是决定实施成本与续费率的那一层。

### 数据模型与取舍

```
custom_field        字段定义（项目 + 问题类型维度）
custom_field_value  字段值（issue_id + field_id 唯一）
```

值以 **JSON 快照**存在 `custom_field_value.value`，而不是给业务表动态加列、也不是纯 EAV。

理由：

| 方案 | 问题 |
|------|------|
| 动态加列 | 每次改 DDL，客户字段数量不可控，且与 `@TableLogic`/实体映射冲突 |
| 纯 EAV 逐字段查 | 一个工作项的 N 个自定义字段要 N 次往返 |
| **JSON 快照（本方案）** | 一次取回整份值，前端直接渲染；代价是**不能按自定义字段做服务端排序/聚合** |

这个代价是明确的：需要按自定义字段过滤时，应走 `QueryController` 的白名单解析（本批未接入自定义字段，
留给后续按字段类型扩展运算符）。

### 支持的类型与校验

`TEXT / TEXTAREA / NUMBER / DATE / SELECT / MULTI_SELECT / USER / CHECKBOX`

校验在服务端集中完成（前端也做一遍给即时反馈，但服务端才是权威）：

- **必填**：保存时对每个必填字段检查非空（含空数组）；
- **NUMBER**：必须是合法数字；
- **DATE**：必须是 `YYYY-MM-DD`；
- **SELECT / MULTI_SELECT**：取值必须在定义时的选项内（防止写进已删除选项）；
- **未知字段**：直接 400 —— 否则客户端可以塞任意 key 堆积垃圾数据；
- **type 创建后不可改**：改了会让已有值的语义漂移（TEXT 改 SELECT，旧值全都不在选项里）。

### 前端

`CustomFieldsSection` 按字段类型渲染控件，已嵌入需求详情与任务编辑弹窗。
采用**派生值**而不是 effect 回填：本地编辑优先，未编辑时用服务端值——
既避免 `react-hooks/set-state-in-effect` 规则，也不会在后台数据刷新时打断用户输入。

## 二、保存的视图（产品化落地）

第 2 批做了结构化查询的**后端**（`POST /query` + `saved_filter` 表），本批补上前端：

- 任务看板工具栏新增「视图」入口：可从已有视图一键载入，或手写表达式后「试运行 → 保存为视图」；
- **视图真正生效**：执行视图时用 `/query` 取回命中任务的 id 集合，看板按 id 过滤，
  顶部显示当前生效的视图与「清除」按钮。
  这样拖拽、看板本身的行为完全不受影响，只是把可见范围缩到视图内；
- 表达式保存前服务端会先解析一次：语法错或用了不存在的字段直接拒绝，
  避免存下一个"永远跑不通"的视图。

## 三、项目集（Program）

企业中大型客户通常是多产品线，需要**管理与汇报边界**（区别于企业的租户/安全边界）：

```
program（企业下） ← project.program_id
```

- 概览接口返回项目清单 + 汇总：项目数、任务总数/已完成、未关闭缺陷、整体进度；
- **汇总口径跟随各项目自己的工作流分类**（项目可自定义状态码，项目集层不能写死 `"DONE"`）；
- 解散项目集先把项目移出，避免留下指向已删除项目集的项目；
- 只允许把项目挂到**同企业**的项目集（跨企业 403）。

## 四、备份与恢复

`scripts/db-backup.sh`：

```bash
scripts/db-backup.sh                                  # 备份
scripts/db-backup.sh restore backups/devflow-xxx.sql.gz # 恢复
```

设计要点（都是踩过的坑）：

- **`--single-transaction`**：InnoDB 一致性快照，不阻塞业务写入；
- **`--set-gtid-purged` 要按能力探测**：这个选项只在 MySQL 5.6+ 的 mysqldump 存在，
  5.5 会直接 `unknown variable` 退出。实测用 `--help | grep` 判断**不可靠**
  （5.5 的帮助文本里也可能出现这个词），因此改成"真的试一次，失败就去掉该选项重试"；
- **校验内容而不是文件大小**：空库也会产生几十字节的 gzip 头，只看大小会把失败当成功。
  现在会检查 dump 里是否含 `CREATE TABLE`；
- **恢复前强制确认 + 自动先备份当前库**：恢复本身也可能出错；
- 口令走 `MYSQL_PWD` 环境变量，不出现在 `ps` 里；
- 保留最近 N 份（默认 14），更早的自动清理。

## 五、验证

集成验证脚本扩展到 **40 项检查**，新增覆盖本批全部能力：

```
✅ 创建自定义字段        ✅ 重复字段标识被拒绝（409）
✅ 必填字段缺失被拒绝    ✅ 保存自定义字段值
✅ 非法选项被拒绝        ✅ 未知字段被拒绝
✅ 自定义字段值可读回    ✅ 创建项目集 / 归集 / 概览
✅ 备份脚本可执行且产出文件
✅ 17 张新表全部创建（原 15 + custom_field + custom_field_value + program）
```

本地实跑：**40/40 全绿**；后端单测 81 项仍全绿；`devflow` 业务库无 CI 数据残留。

## 六、本批未做

- **自定义字段接入结构化查询**：需要按字段类型扩展运算符（数字比较 / 日期范围 / 多选包含），
  并处理"JSON 快照"的查询代价，属于设计题而非机械活；
- **保存视图的多渲染器**（同一查询挂看板/列表/时间线）：当前只做了"列表过滤"这一种；
- **项目集跨项目里程碑与资源再平衡**：概览已有，规划视图未做；
- **定时备份调度**：脚本可用，但没接到 cron/Quartz。**备份最重要的是"真的跑过恢复"**，
  建议先在测试环境定期演练，再谈自动化。
